# Movie API

Сервис на Go с HTTP и gRPC API для работы с каталогом фильмов. PostgreSQL используется как основное хранилище данных, а Redis - для поиска по обратному индексу и кэширования ответов `/search`.

## Запуск

1. Подключение к PostgreSQL и автоматическое накатывание SQL-миграций через `goose`.
2. Синхронизация с внешним стендом, начиная с `max(id) + 1`, чтобы не создавать дублей.
3. Подключение к Redis, очищает старый кэш поиска и строит обратный индекс по всем фильмам из PostgreSQL.
4. Запускаются gRPC- и HTTP-серверы.

## Переменные окружения

- `DATABASE_URL` - строка подключения к PostgreSQL.
- `REDIS_ADDR` - адрес Redis в формате `host:port`, без пароля (по умолчанию `localhost:6379`).
- `MOVIE_BASE_URL` - базовый URL внешнего фильм-стенда (по умолчанию `https://homeworksite.site`).
- `HTTP_ADDR` - адрес HTTP-сервера (по умолчанию `:8080`).
- `GRPC_ADDR` - адрес gRPC-сервера (по умолчанию `:50051`).

## Этапы запуска сервиса

1. Убедиться, что локально запущены PostgreSQL (порт `5432`) и Redis (порт `6379`).
```bash
brew services start postgresql@<ваша версия>
brew services start redis
```


2. Из корня репозитория (где лежит `go.mod`) запустить приложение:
```bash
DATABASE_URL="postgres://<логин:пароль>@localhost:5432/postgres?sslmode=disable" \
REDIS_ADDR="localhost:6379" \
go run ./cmd/app
```

После запуска документация Swagger UI доступна по адресу `http://localhost:8080/swagger/index.html`.

## Поиск и структура данных в Redis

- **Токенизация:** индексируются названия фильмов (`title`) и режиссёры (`director`).
- **Обратный индекс (`index:word:<слово>`):** хранится в Redis как множество (`Set`), содержащее `id` фильмов, в которых встречается это слово. Ключи индекса хранятся бессрочно (без TTL), а структура `Set` исключает дубли при повторной индексации.
- **Многословный поиск:** реализован по логике **AND**. Для всех слов из запроса `q` в Redis вычисляется пересечение множеств `id` командой `SINTER`, после чего по найденным идентификаторам фильмы зачитываются из PostgreSQL.
- **Кэш ответов (`cache:search:<запрос>`):** успешный JSON-ответ `/search` сохраняется в Redis как строка с TTL **3600 секунд** (1 час). Повторный запрос с тем же `q` отдаётся напрямую из Redis без обращения к PostgreSQL, TTL при чтении не обновляется. Ошибки `400` и `500` не кэшируются. При перезапуске сервиса и пересборке индекса старый кэш удаляется.

## Примеры запросов

Поиск по названию без учёта регистра:
```bash
curl -i "http://localhost:8080/search?q=SOLARIS"
```

Поиск по режиссёру (несколько слов, пересечение по AND):
```bash
curl -i "http://localhost:8080/search?q=Andrei%20Tarkovsky"
```

Запрос без совпадений (вернёт `200 OK` и пустой массив `[]`):
```bash
curl -i "http://localhost:8080/search?q=nonexistentmovie123"
```

Пустой или состоящий из пробелов запрос (вернёт `400 Bad Request`):
```bash
curl -i "http://localhost:8080/search?q=%20%20"
```
